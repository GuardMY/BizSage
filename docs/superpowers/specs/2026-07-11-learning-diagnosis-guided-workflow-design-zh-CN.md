# 学习与诊断 Agent 引导式工作流设计
**日期：** 2026-07-11

## 目标

为学习 Agent 与诊断 Agent 补齐“自我介绍、右侧快捷提问栏、基于上下文的下一步引导、可持续排序的高频问题池、以及诊断结束条件”这套引导式工作流。

本设计同时覆盖：
- Web 前端交互
- 后端 API 数据结构与接口
- `services/ai-worker` 的提示词、上下文与输出结构
- 问题池持久化与排序逻辑

## 背景与缺口

当前实现已经具备诊断、学习、模式切换、SSE 流式输出、RAG、记忆与报告生成底座，但缺少以下能力：
- Agent 不会稳定地先介绍自己“能做什么、怎么配合用户”
- 右侧没有基于当前对话动态更新的“下一步可问什么”
- 没有学习/诊断共用的高频问题池与排序机制
- 诊断流程没有显式的“前期计划、补齐画像、允许继续补充、识别可结束”的状态

## 设计原则

1. 右侧推荐栏必须高可利用，优先给用户“下一步最省力的问题”。
2. 推荐项要动态生成，但不能完全依赖实时 LLM，即需结合历史使用数据做稳定排序。
3. 学习与诊断共用相同的数据骨架，但使用不同的意图、节奏和终止条件。
4. 诊断必须能在“信息不足”时主动推进问诊，而不是直接给空泛结论。
5. 用户始终保留三种选择：继续追问、点快捷问题、刷新推荐。

## 用户体验

### 1. 学习 Agent

首轮进入学习 Agent 时，先输出一段固定结构的自我介绍：
- 说明它是行业学习助手
- 说明能帮用户理解行业节点、规则、指标、风险、机会
- 说明它会根据当前对话推荐下一步可学内容
- 说明右侧快捷栏可直接点击，随时可刷新

右侧快捷栏展示三类问题：
- 下一步最可能感兴趣的节点
- 当前节点的更细颗粒度区块
- 与当前上下文相关的延展方向

### 2. 诊断 Agent

首轮进入诊断 Agent 时，先输出一段固定结构的自我介绍：
- 说明它是经营诊断助手
- 说明会先摸底经营现状，再分层诊断
- 说明会按计划向用户提问
- 说明右侧快捷栏会给出最可能的经营问题和补充信息点

对话前期，Agent 要先给出诊断计划草案，例如：
- 您从事什么行业
- 是否实体经营
- 投资金额大致多少
- 门店/仓储/人员规模
- 营收、成本、利润、客流、渠道的基本情况

右侧快捷栏展示三类问题：
- 最可能出现的经营问题
- 当前阶段最缺的经营画像字段
- 可能影响诊断结论的关键细节

## 推荐栏逻辑

### 1. 实时候选生成

每轮对话结束后，AI Worker 根据当前对话内容生成 `recommendationCandidates`：
- 学习 Agent 产出可学习节点/区块/方向/细节
- 诊断 Agent 产出可追问的经营问题/补充字段/风险点

候选生成来源：
- 当前用户问题
- 当前对话上下文
- 当前命中的知识/情报/记忆
- 当前 Agent 状态

### 2. 高频问题池

每个行业维护一个持久化问题池，问题粒度包括：
- 节点级问题
- 区块级问题
- 细节级问题
- 追问级问题

每条问题记录以下指标：
- `topLevelScore`：由 LLM 结合行业结构判断的优先级
- `usageCount`：历史被点击/被使用次数
- `ratingAvg`：用户平均评分
- `ratingCount`：评分次数
- `lastUsedAt`：最近使用时间
- `status`：启用、隐藏、归档

### 3. 排序规则

推荐排序采用混合分数：
- LLM 判断分
- Top 级别分
- 使用频次分
- 评分分
- 新鲜度惩罚或加分

排序目标：
- 既体现“当前上下文最相关”
- 也体现“历史上最有用”
- 同时避免长期只展示热门项，导致推荐塌缩

### 4. 刷新行为

如果用户不想点现有推荐，可以手动刷新：
- 学习 Agent 刷新为“新一轮最可能想学什么”
- 诊断 Agent 刷新为“新一轮最可能想补什么经营信息”

刷新必须保留：
- 当前对话上下文
- 当前行业
- 当前 Agent 状态
- 最近已展示过的问题黑名单

## 诊断流程状态

诊断 Agent 按状态推进：

1. `INTRO`
- 先介绍功能和交互方式
- 展示本轮诊断计划

2. `PROFILE_GATHERING`
- 采集基础经营画像
- 重点补齐缺口字段

3. `ISSUE_HYPOTHESIS`
- 由 LLM 根据当前画像归纳最可能的核心经营问题

4. `DETAIL_PROBING`
- 针对核心问题追问可影响结论的关键细节

5. `READY_TO_CLOSE`
- LLM 判断信息足以生成诊断报告
- 用户仍可选择继续补充

6. `CLOSED`
- 生成诊断报告
- 固化本轮结论、证据与记忆候选

## 结束条件

诊断是否结束，由 LLM + 规则双重判断：
- 当前经营画像字段达到最低阈值
- 核心问题已收敛到 1-3 个主问题
- 关键冲突/缺口已显式标记
- 诊断建议已能形成分级行动项

允许继续补充的场景：
- 用户主动说还有补充
- LLM 标记尚未充分
- 关键指标不一致
- 用户希望先解释某个问题再收口

## API 设计

### 1. 会话元数据

为学习与诊断会话增加可持久化状态字段：
- `agentMode`
- `workflowStage`
- `profileCompleteness`
- `primaryIssueTags`
- `recommendedQuestionIds`
- `closedBy`
- `closedReason`

### 2. 推荐栏接口

新增推荐数据接口，返回：
- 当前推荐问题列表
- 每条推荐的来源与排序分
- 是否可刷新
- 当前黑名单/去重信息

### 3. 问题池接口

新增问题池维护接口：
- 查询行业问题池
- 新增/更新问题
- 批量回写使用次数
- 回写评分
- 刷新 top 问题缓存

### 4. 诊断状态接口

新增会话状态推进接口：
- 上报当前诊断阶段
- 上报是否允许结束
- 上报用户是否选择继续补充

## AI Worker 设计

### 1. 学习 Agent

学习 Agent 输出需扩展为：
- `answer`
- `recommendationCandidates`
- `currentTopic`
- `nextBestTopics`
- `memoryCandidates`

### 2. 诊断 Agent

诊断 Agent 输出需扩展为：
- `answer`
- `recommendedQuestions`
- `workflowStage`
- `profileMissingFields`
- `completionSignal`
- `memoryCandidates`

### 3. Prompt 结构

系统提示词需要新增两类指令：
- 自我介绍与交互解释
- 引导式推荐与收口判断

诊断模式 prompt 还需新增：
- 主动采集画像字段
- 先问基础经营现状
- 缺口优先原则
- 允许用户继续补充

学习模式 prompt 还需新增：
- 根据当前上下文给出下一步最值得学的内容
- 避免一次性铺太多
- 对热门问题与长尾问题做平衡

## 排序与持久化

问题池建议以行业维度持久化，必要时再按地区/会员等级分层。

更新策略：
- 用户点击快捷问题后，`usageCount + 1`
- 用户打分后，更新 `ratingAvg` 与 `ratingCount`
- LLM 重新判定 top 级别时，更新 `topLevelScore`
- 定时任务周期性重排，并写回缓存字段

## 兼容策略

1. 现有单轮诊断与学习接口保持可用。
2. 新增推荐栏字段为向后兼容扩展，旧前端可忽略。
3. 诊断结束信号先以软状态返回，不强制中断当前会话。
4. 右侧推荐为空时，必须允许用户继续手动输入。

## 验收标准

学习 Agent：
- 首轮能明确介绍自身功能和交互逻辑
- 右侧能显示基于上下文更新的下一步学习问题
- 可按行业问题池排序快捷问题
- 支持刷新推荐

诊断 Agent：
- 首轮能明确介绍自身功能和交互逻辑
- 前期能输出诊断计划与缺失画像字段
- 右侧能显示最可能的经营问题
- 能在 LLM 判断可结束时给出收口信号
- 用户可选择继续补充再生成报告

后端与 AI Worker：
- 推荐栏数据可持久化
- 问题池可按行业查询、更新和排序
- 流式接口可携带推荐与阶段信息
- 诊断/学习输出可扩展而不破坏既有主链路
