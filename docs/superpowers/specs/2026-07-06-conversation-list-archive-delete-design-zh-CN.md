# 会话列表归档与删除设计

**日期：** 2026-07-06

## 目标

让会话侧边栏与当前工作区页签保持一致，并支持直接在列表中管理会话：
- 在诊断工作区显示诊断专用列表标题；
- 在归档工作区显示归档专用列表标题；
- 在诊断会话列表中直接归档活跃会话；
- 在归档会话列表中直接软删除已归档会话。

## 当前背景

- Web 端已经通过 `apps/web/lib/conversation-workspace.ts` 按页签拆分可见会话。
- 诊断工作区主面板已经支持对当前选中会话执行归档。
- API 目前已经支持 `ACTIVE` 和 `ARCHIVED` 两种会话状态，但还没有提供软删除动作。

## 选定方案

1. 继续使用状态驱动会话生命周期。
   - 复用现有 `status` 字段，新增软删除终态 `DELETED`。
   - 数据库表结构保持不变，因为 `status` 列本身就是普通字符串。
2. 在常规列表接口中过滤已删除会话。
   - `GET /api/conversations` 继续只返回活跃和归档记录。
   - 软删除后的会话不再出现在诊断或归档工作区。
3. 将删除暴露为受鉴权保护的会话动作。
   - 新增专用 API 端点用于软删除。
   - Web UI 仅允许对已归档会话显示删除操作。
4. 将交互收敛在侧边栏内部。
   - 诊断列表项增加直接归档动作。
   - 归档列表项增加直接删除动作。
   - 现有主面板“归档当前会话”入口继续保留。

## 交互细节

### 侧边栏标题

- `diagnosis` 页签标题：`诊断会话列表` / `Diagnosis conversation list`
- `archive` 页签标题：`归档会话列表` / `Archive conversation list`
- 这些列表不再使用 `当前上下文` / `Current context` 作为眉标题文案。

### 列表项动作

- 在诊断页：
  - 每条活跃会话右侧显示归档动作；
  - 点击归档动作时不能同时触发行选中。
- 在归档页：
  - 每条已归档会话右侧显示删除动作；
  - 删除必须是数据库软删除。

### 选中规则

- 在诊断列表中归档当前会话后，应自动选中下一个仍可见的活跃会话。
- 在归档列表中删除当前会话后，应自动选中下一个仍可见的归档会话。
- 当前页签没有任何可见会话时，选中态应回到 `null`。

## 错误处理

- 归档和删除失败应继续通过现有页面状态/报错流展示。
- 未授权或登录过期仍沿用现有的鉴权失效处理路径。

## 测试

- API 集成测试：
  - 创建并归档一个会话；
  - 对该会话执行软删除；
  - 确认它不会再出现在 `GET /api/conversations` 结果中。
- Web 回归测试：
  - 已删除会话不会进入活跃/归档分组；
  - 按页签返回正确的侧边栏标题与操作文案。
