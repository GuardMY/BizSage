## 第一部分：风险全景

### 1.1 风险分类框架

BizSage 产品覆盖三大核心模块（入行学习 Agent、经营诊断 Agent、全网情报感知后台），全系统风险划分为四大类别，共计 22 项具体风险。分类框架如下：

| 风险大类 | 风险数量 | 核心关注领域 | 优先级 |
|---------|---------|-------------|-------|
| 法务合规风险 | 8 项 | 爬虫合规、隐私保护、版权、资质、数据跨境、内容合规 | 最高优先级 |
| 商业竞争风险 | 4 项 | 产品复刻、竞品分流、大厂挤压、定价策略 | 高优先级 |
| 技术系统风险 | 6 项 | 反爬、幻觉、知识库质量、数据库、安全、API 依赖 | 高优先级 |
| 运营用户风险 | 4 项 | 用户纠纷、服务匹配、履约舆情 | 中优先级 |

---

### 1.2 法务合规风险（8项）

#### 风险 F1：爬虫侵权

| 属性 | 内容 |
|------|------|
| **风险名称** | 批量抓取商业网站、付费研报、大宗商品数据，侵犯著作权、构成不正当竞争 |
| **风险等级** | 4 级（致命） |
| **发生概率** | 高 |
| **影响评估** | 诉讼赔偿、平台关停、行政处罚 |
| **涉及模块** | 情报感知引擎 |

#### 风险 F2：名誉侵权

| 属性 | 内容 |
|------|------|
| **风险名称** | 抓取负面舆情、行业爆料未经核验推送，引发企业名誉侵权起诉 |
| **风险等级** | 4 级（致命） |
| **发生概率** | 中高 |
| **影响评估** | 名誉侵权诉讼、赔偿、公关危机 |
| **涉及模块** | 情报感知引擎、经营诊断 Agent |

#### 风险 F3：政策解读偏差

| 属性 | 内容 |
|------|------|
| **风险名称** | AI 自动解读政策出现偏差，误导商家经营决策，用户追责索赔 |
| **风险等级** | 4 级（致命） |
| **发生概率** | 中 |
| **影响评估** | 用户索赔、监管约谈、品牌信誉受损 |
| **涉及模块** | 入行学习 Agent、经营诊断 Agent |

#### 风险 F4：隐私泄露

| 属性 | 内容 |
|------|------|
| **风险名称** | 用户录入营收、供应商、门店地址、客户信息、联系方式未脱敏，违反《个人信息保护法》；未经授权使用用户数据训练模型；会话日志长期留存泄露 |

| **发生概率** | 中 |

| **风险等级** | 3 级（重要） |
| **发生概率** | 中 |
| **影响评估** | 版权诉讼、内容下架、赔偿 |
| **涉及模块** | 行业知识库 |

#### 风险 F6：无证咨询

| 属性 | 内容 |
|------|------|

| **影响评估** | 监管处罚、非法经营认定 |

#### 风险 F7：跨境数据合规

| **风险等级** | 3 级（重要） |

## 第二部分：风险规避与消减措施

### 2.1 法务风险规避

#### 2.1.1 爬虫侵权（F1）- 对应措施

| 措施类型 | 具体措施 | 落地方式 |
|---------|---------|---------|
| **前置规避** | 数据源分层权限抓取规则 | 政务官网（发改委、市监局、海关）允许全量定时抓取；付费行业平台禁止主动爬虫，仅官方 API 合作采购；自媒体/论坛仅抓取公开短摘要（不超过200字） |
| **前置规避** | 爬虫行为合规约束 | 抓取间隔强制最低3秒，单站点并发不超过2；自动校验 robots.txt，禁止抓取禁止路径 |
| **前置规避** | 代理池限速 | 降低轮换频率，不使用海量高匿代理批量爬取 |
| **事中控制** | 内容标注规范 | 所有抓取情报强制标注来源、原文链接；引用内容仅作行业参考，不完整转载、不商用二次售卖情报原文 |
| **事中控制** | 付费内容防护 | 付费数据仅通过官方开放 API 合作采购，不私自爬取 |
| **事后兜底** | 法务月度巡检 | 每月全量巡检爬虫规则，提前排查合规漏洞 |

#### 2.1.2 名誉侵权（F2）- 对应措施

| 措施类型 | 具体措施 | 落地方式 |
|---------|---------|---------|
| **前置规避** | 情报双层校验机制 | 单条负面信息仅单一自媒体来源：自动标记"存疑"，前端弱化展示，不标注4级重大风险 |
| **前置规避** | 多源佐证规则 | 同一负面事件需3个及以上权威媒体/官方公告佐证，才标记正式风险，否则仅归档不主动推送 |
| **事中控制** | 负面内容脱敏处理 | 情报不直接点名中小企业全称，仅描述行业共性问题；涉及头部企业自动增加免责标注 |
| **事后兜底** | 企业申诉通道 | 后台搭建企业申诉入口，收到名誉侵权投诉24小时内下架对应情报，人工复核后判定是否恢复展示 |

#### 2.1.3 政策解读偏差（F3）- 对应措施

| 措施类型 | 具体措施 | 落地方式 |
|---------|---------|---------|
| **前置规避** | 强制固定免责前缀 | 所有政策解读、政策推演内容头部统一加载免责声明：「本解读仅基于公开资讯 AI 自动推演，不构成官方经营指导」 |

## 第三部分：数据质量标准

### 3.1 数据质量维度定义

基于系统五层数据存储结构和知识库标准化规范，定义以下数据质量维度：

| 维度 | 定义 | 衡量指标 |
|------|------|---------|
| **完整性** | 每条数据是否携带完整的五维标签 | 标签完整率（行业ID、链路节点ID、地域标签、置信度、信息类型） |
| **准确性** | 数据内容是否与真实行业情况一致 | 内容错误率、指标偏差率 |
| **一致性** | 跨数据源、跨时间点的数据无矛盾 | 新旧信息冲突率、多源校验通过率 |
| **时效性** | 数据的更新及时程度 | 抓取到入库延迟时间、过时数据占比 |
| **合规性** | 数据内容是否符合法律法规及引用规范 | 侵权内容占比、脱敏合规率、授权合规率 |
| **可追溯性** | 数据来源是否可查、可验证 | 来源标注率、数据源ID绑定率 |
| **原创性** | 知识库内容是否经过人工改写而非直接复制 | 原文复制率、改写通过率 |

**五层数据存储结构（核心底层）：**

| 层级 | 名称 | 说明 |
|------|------|------|
| 第1层 | 显性标准层 | 官方流程、国标、行标、SOP、合规条文 |
| 第2层 | 量化指标层 | 细分 KPI、公式、阈值、优秀/及格/不及格区间 |
| 第3层 | 隐形行规层 | 圈内默认习惯、不公开操作、私下结算规则 |
| 第4层 | 风险漏洞层 | 亏损坑点、合规红线、诈骗点、扯皮点 |
| 第5层 | 链路联动层 | 上游影响因子、下游传导结果、全链波动关系 |

**行业隔离架构：** 每个行业独立数据库实例，行业之间数据完全隔离，避免化工/食品/汽车逻辑串混，支持行业一键切换及双行业对照模式。

### 3.2 质量验收标准

#### 3.2.1 数据质量量化目标

| 质量维度 | 目标值 | 告警阈值 | 不可接受阈值 |
|---------|-------|---------|------------|
| 标签完整率 | >= 99.5% | < 98% | < 95% |
| 内容准确率（抽检） | >= 99% | < 97% | < 95% |
| 新旧信息冲突率 | <= 0.5% | > 1% | > 3% |
| 情报入库延迟 | <= 30分钟 | > 1小时 | > 4小时 |
| 过时数据占比（活跃库） | <= 5% | > 10% | > 20% |
| 来源标注率 | 100% | < 100% | — |
| 原文复制率 | 0% | > 0% | > 5% |

#### 3.2.2 知识库录入标准

| 检查项 | 标准要求 |
|-------|---------|
| 内容原创性 | 运营录入仅参考资料逻辑，全部重新改写行文，禁止直接复制原文 |
| 数据指标引用 | 仅提取公开通用行业均值，不摘抄付费报告专属调研数据 |
| 引用标注 | 参考公开白皮书、政府统计数据，内容末尾统一标注数据来源 |
| 标签强制绑定 | 每条数据必须带标签：公开信息/内部行规/灰色规则/风险红线；所属环节（上游/中游/下游）；影响对象（成本/效率/利润/风险）；关联指标 ID |
| 双人复核 | 录入员 + 审核员两次校验才能上线 |
| 禁止收录 | 禁止收录付费专业书籍、付费行业专栏完整内容 |

#### 3.2.3 情报数据质量验收

| 检查项 | 标准要求 |
|-------|---------|
| 指纹去重 | URL 指纹 + 文本相似度双重去重 |
| 垃圾过滤 | 广告、营销软文、无关内容直接丢弃 |
| 正文提取 | 剥离导航、弹窗、广告块，仅保留标题+正文 |
| 统一格式化 | 时间戳、来源名称、地域标签、原文 URL 标准化 |
| 数值抽取 | 自动提取涨幅、价格、补贴、产能、税率等量化数值 |
| 基础结构化字段 | 情报 ID、行业 ID 数组、来源类型、来源名称、原文 URL、发布时间、抓取时间、地域标签、原始标题、正文摘要、量化数值集合、原始置信度、来源权重等级 |

### 3.3 质量监控机制

#### 3.3.1 自动化监控

| 监控项 | 监控方式 | 告警条件 | 响应要求 |
|-------|---------|---------|---------|
| 抓取成功率 | 实时统计各站点抓取成功率 | 单站点成功率低于 90% | 运维 2 小时内修复 |

| 数据源健康度 | 定时探测数据源可用性 | 数据源连续 3 次不可用 | 自动切换备用源 + 告警 |

#### 5.3.3 持续改进机制

1. **风险库动态更新**：每次识别出新风险或现有风险发生变化，即时更新风险清单及相关防控措施配置
2. **措施有效性评估**：每次风险处置完成后，评估措施的及时性、充分性、有效性，优化标准作业流程
3. **外部法规跟踪**：法务负责人持续跟踪《个人信息保护法》《数据安全法》《网络安全法》及行业监管动态，及时调整合规策略
4. **用户反馈闭环**：用户纠错、投诉、申诉数据月度汇总分析，识别系统性风险隐患，驱动产品与运营优化
