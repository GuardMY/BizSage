# V1/V2 实装收敛设计

## 范围

本次变更关闭治理文档回顾中发现的最重要实现差距：

1. 将 API 核心 V1/V2 路径从内存存储替换为 MySQL 持久化仓库。
2. 修复 API、AI worker、Web 和种子 SQL 中用户可见的乱码文本。
3. 将 Web 控制台的登录、诊断、付费情报、报告元数据和运维指标接入真实 API。
4. 重新执行仓库验证命令，并更新无法执行项目的验证记录。
5. 在不实现完整 V3 商业流程的前提下，将 V2 骨架数据尽量变成可追踪、可持久化的数据。

## 设计

API 使用 Spring `JdbcTemplate` 仓库，不引入更重的 ORM 层。这样可以保持现有控制器契约稳定，同时让运行时数据在进程重启后保留。仓库测试覆盖登录用户、会话、知识导入、免费情报、付费情报权益过滤和诊断报告来源过滤。

AI worker 和 Web 保持当前简单结构。worker 返回可读 UTF-8 中文兜底文本，并保留证据、时效性、置信度、自检状态和免责声明。Web 仍是单页工作台，但核心交互改为调用 `lib/api-client.ts`，不再依赖静态 mock 数据。

collector 的 V2 韧性 helper 在本轮保持轻量。验证文档会区分本次实际执行的检查，以及受 Docker、压测或长稳环境限制仍阻塞的检查。

## 非目标

- 不做完整 JPA 迁移。
- 不做完整 Celery/Redis/XXL-JOB 爬虫平台。
- 不做完整 GraphRAG 或 Qdrant 生产集成。
- 不做会员计费、订单、发票或会员中心。
- 不生成真正 PDF 二进制文件；除非时间允许，报告元数据仍作为 V2 交付面。

## 验收

- API 测试证明仓库持久化行为和统一响应契约。
- AI worker 测试证明可读输出，以及无证据/冲突场景的受控响应。
- Web 测试证明 API-client 解析和至少一个真实数据加载路径。
- 英中文档、里程碑验证记录和变更日志同步更新。
