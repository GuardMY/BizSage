# BizSage V3 管理员后台界面设计方案

## 1. 设计目标

V3 管理员后台用于维护 BizSage 的完整商业化运营闭环，覆盖知识、采集、情报、复核、风控、会员、订单、告警、审计、合规和运营报表。它不是用户侧对话产品的附属页面，而是面向运营、审核、爬虫运维、法务、财务、管理员和超级管理员的日常工作台。

后台应复用现有 `apps/web` 的 Next.js App Router、React、`lucide-react` 图标、工作台式侧边栏、顶部身份区、卡片、表格、弹窗和中英文文案结构，但需要提高信息密度，减少对话式视觉，强化筛选、批量操作、双人复核、权限边界和审计追踪。

## 2. 用户角色与权限边界

| 角色 | 核心任务 | 默认可见模块 | 高风险限制 |
|---|---|---|---|
| 超级管理员 | 全局配置、权限、合规开关、生产发布审批 | 全部模块 | 关键配置需二次确认和审计留痕 |
| 管理员 | 运营配置、人员权限、告警处理、报表查看 | 总控台、用户会员、告警、日志、合规、报表 | 无法绕过双人复核查看用户明文私有数据 |
| 运营人员 | 情报复核、人工情报录入、知识巡检、用户补偿 | 知识库、情报、台账、人工情报、用户会员 | 不可修改系统级风控阈值 |
| 审核人员 | 情报真假、冲突、申诉、合规复核 | 情报、台账、合规、日志 | 无法配置数据源和会员权益 |
| 爬虫运维 | 数据源、调度、代理、抓取质量和成本 | 采集调度、告警、日志、报表 | 无法处理用户会员和订单 |
| 法务/合规 | 免责文案、灰色内容、巡检报告、审计证据 | 合规、日志、台账、报表 | 仅可读用户业务数据摘要 |
| 财务/商业运营 | 订单、权益、成本、付费转化 | 商业化、用户会员、报表 | 不可编辑情报内容和风控规则 |
| 只读观察员 | 稳定性、运营质量、审计查询 | 总控台、报表、日志只读 | 无写操作 |

所有页面都必须执行功能权限和数据权限双层校验，并按用户、地域、行业、会员权益四层隔离过滤数据。用户私有经营数据默认只显示脱敏摘要，任何可逆查看都必须进入双人授权流程。

## 3. 信息架构

后台采用左侧分组导航 + 顶部上下文栏 + 主内容区 + 右侧详情抽屉的结构。

| 导航分组 | 模块 | 主要页面 |
|---|---|---|
| 总览 | 运营总控台 | 业务健康、风险待办、SLA、成本、复核队列、商业化指标 |
| 知识与情报 | 行业知识库、情报管理、人工情报、台账工单 | 知识树、版本对比、情报列表、复核工作台、冲突/谣言/申诉台账 |
| 采集与治理 | 采集调度、数据源、关键词、风控规则、数据生命周期 | 数据源状态、任务调度、代理健康、规则配置、冷热归档 |
| 商业化 | 用户会员、订单权益、报告交付、投稿激励 | 用户列表、会员补偿、订单流水、权益配置、报告下载记录 |
| 运维安全 | 告警中心、监控指标、日志审计、权限管理 | 告警处理、服务指标、操作日志、RBAC 策略 |
| 合规报表 | 合规配置、巡检任务、月度运营报表 | 免责文案、灰色内容开关、巡检报告、运营导出 |

桌面端左侧导航宽度建议沿用现有工作台 `320px`，但后台可折叠为 `72px` 图标栏。移动端 V3 主要支持应急处理和只读查询，复杂表格以横向滚动或卡片摘要降级。

## 4. 全局布局与复用策略

| 现有前端资产 | 后台复用方式 | 需要增强 |
|---|---|---|
| `WorkspaceShell` 工作台壳 | 作为 `AdminShell` 的基础布局参考 | 支持导航分组、折叠、环境标识、告警入口 |
| `.rail` 侧边栏 | 复用深色导航视觉 | 增加二级菜单、徽标计数、只读模式提示 |
| `.topbar` 顶部栏 | 复用身份、语言、退出登录结构 | 增加环境、租户/行业/地域筛选、全局搜索 |
| `.workspaceCard` | 复用为指标卡、详情卡、配置区块 | 后台卡片半径建议不超过 8px，减少装饰阴影 |
| `.table` / `.row` | 复用为低密度列表 | 新增真实表格、批量选择、列固定、分页、排序 |
| `.modal` | 复用确认、详情和授权弹窗 | 增加右侧抽屉、全屏编辑器、双人复核弹窗 |
| `lucide-react` | 继续作为按钮和导航图标来源 | 图标按钮必须有 `title` 和可访问标签 |

视觉风格应延续现有绿色、钢蓝、琥珀、红色状态体系，但后台页面以白色和浅灰工作面为主。告警、风险、合规状态使用颜色作为辅助信号，同时必须保留文字标签，避免仅依靠颜色判断。

## 5. 关键页面设计

### 5.1 运营总控台

首页直接进入可操作工作台，不做营销式欢迎页。

顶部指标区显示：今日新增情报、待复核情报、P0/P1 告警、API 成功率、爬虫成功率、AI 自检通过率、缓存命中率、订单金额、付费转化、SLA 本月可用性。

主区分四块：风险待办、生产健康、情报生产、商业化。每块都显示当前状态、趋势、负责人和下一步操作，支持进入复核、确认告警、打开日志、触发降级预案、查看订单和导出报表。

### 5.2 行业知识库管理

页面采用三栏结构：左侧行业与链路树，中间知识节点编辑区，右侧版本、证据和复核面板。

必备控件包括行业链路树、表单/JSON 双模式内容编辑器、版本对比、双人复核、批量巡检。编辑人提交后进入待复核，复核人不能是同一账号。巡检应覆盖过期、缺源、冲突、低置信检查。

### 5.3 采集调度管理

页面围绕“数据源 -> 任务 -> 入库质量 -> 成本”组织。表格列建议包含来源名称、类型、权重、行业覆盖、地域覆盖、抓取周期、并发上限、成功率、封禁率、成本、最近抓取、状态、负责人和操作。

详情抽屉展示 robots/合规说明、请求头策略、代理池、失败重试、死信队列、最近 24 小时趋势、关联关键词和黑名单规则。高风险操作如停用核心来源、提高并发上限、跳过合规检查，必须弹出影响范围和回滚方式确认。

### 5.4 情报管理与复核工作台

情报页面需要同时支持列表检索和队列式复核。

| 视图 | 使用场景 | 核心交互 |
|---|---|---|
| 情报总览 | 快速掌握新增、待复核、已归档、付费情报 | 指标卡 + 趋势 + 快捷筛选 |
| 情报列表 | 批量检索、筛选、归档、导出 | 多条件筛选、列排序、批量操作 |
| 复核工作台 | 逐条判断真伪、冲突、严重等级 | 左证据链、中内容、右裁决栏 |
| 详情抽屉 | 不离开列表查看上下文 | 来源、血缘、相似情报、历史版本 |

复核裁决必须包含：通过、驳回、标记存疑、升级工单、转合规、设为付费情报、归档。每次裁决记录复核人、时间、理由、证据和前后字段差异。

### 5.5 台账工单管理

台账包括虚假谣言、新旧冲突、申诉、告警、合规巡检和敏感数据查看申请。页面采用工单队列设计：左侧筛选，中央工单表，右侧处理时间线。每个工单显示严重级别、影响行业/地域、关联情报、当前状态、处理人、SLA 剩余时间和下一步动作。

状态流转建议：新建 -> 已认领 -> 处理中 -> 等待复核 -> 已关闭 -> 已归档。P0 工单必须支持升级负责人和通知记录。

### 5.6 人工情报管理

人工情报负责补齐本地扫盲、付费圈层、用户投稿和合作伙伴来源。录入字段包括城市、行业、链路节点、内容、来源类型、采集人、发生时间、置信度、权益级别、附件、脱敏说明、有效期。录入后默认进入审核队列，不直接参与用户端推理。

付费情报权限管理必须清楚展示：免费不可见、普通付费、高阶付费、内部可见、法务冻结。冻结状态应阻止 API 输出和报告引用。

### 5.7 风控规则配置

风控页面分为谣言识别、冲突判定、灰色内容、AI 输出自检、接口防刷、付费内容保护六个 Tab。阈值用滑块或数字输入，规则启停用开关，适用范围用多选，风险级别用分段控件，变更生效方式用单选。保存前显示影响范围、回滚版本和灰度环境。

所有规则变更必须产生审计日志，并支持版本回滚。

### 5.8 用户、会员、订单与权益

用户会员页面按“用户画像 -> 权益 -> 使用记录 -> 风险与合规”组织。

| 页面 | 核心信息 | 操作 |
|---|---|---|
| 用户列表 | 账号、地域、行业、会员等级、最近活跃、报告数、风险标记 | 搜索、冻结、备注、查看摘要 |
| 用户详情 | 基础资料、画像标签、会话摘要、报告、订单、权益 | 补偿会员、调整角色、发起数据查看申请 |
| 会员权益 | 免费、普通付费、高阶付费、企业/内部 | 配置可见情报、报告额度、导出权限 |
| 订单流水 | 订单号、金额、状态、渠道、发票、退款 | 查询、导出、退款审核 |
| 投稿激励 | 投稿、审核、奖励、排行榜 | 审核投稿、结算会员时长 |

管理员不得直接查看用户明文经营数据。需要查看时进入“敏感数据访问申请”工单，由双人审批后显示有限时间、有限字段、带水印的查看界面。

### 5.9 告警中心与监控指标

告警中心按 P0/P1/P2 分级，支持确认、认领、静默、升级、转工单和关闭。监控指标分为服务健康、数据库、爬虫、API、AI 推理、缓存、队列、业务指标、成本指标。每个指标页面提供当前值、阈值、趋势、关联日志和建议处理步骤。

P0 告警详情必须展示触发时间、影响范围、关联服务、最近变更、自动降级结果、通知记录、负责人、恢复目标和复盘入口。

### 5.10 日志审计

日志审计必须支持按流水号、用户、管理员、情报、报告、订单、时间、IP、操作类型检索。日志分类包括操作日志、抓取日志、AI 推理日志、权限日志、敏感数据访问日志、订单日志、合规日志、申诉日志。

详情页必须展示请求链路、前后字段变化、权限命中、数据范围、脱敏状态、结果码、异常堆栈摘要和可导出的审计证据包。

### 5.11 合规配置与巡检

合规页面包含免责文案、用户协议、隐私协议、灰色内容隐藏、封禁信息盲区、月度巡检、法务证据包。文案编辑器必须支持版本化、预览、提交复核、发布和回滚。灰色内容一键隐藏需要显示将影响的情报数量、报告引用数量和用户端展示变化。

月度合规巡检任务列表应包含知识库巡检、爬虫合规、AI 输出抽检、用户授权检查、付费内容隔离检查、审计日志留存检查。

### 5.12 月度运营报表

报表中心提供固定模板和自定义导出。固定模板包括情报生产月报、用户增长月报、付费转化月报、告警与 SLA 月报、合规巡检月报、成本月报、报告交付月报。导出格式支持 PDF、CSV 和内部审计包。导出付费情报或敏感日志时必须记录导出范围和审批单号。

## 6. 关键业务流程

```text
情报入库到用户可见:
采集/人工录入 -> 清洗去重 -> 风险与冲突识别 -> 待复核队列 -> 审核通过 -> 权益级别确认 -> 知识库/情报库同步 -> 用户端检索与报告引用 -> 后台审计可追溯

知识库版本发布:
编辑草稿 -> 自动字段校验 -> 来源与置信度检查 -> 提交复核 -> 第二人审批 -> 灰度发布 -> 观察指标 -> 全量发布或回滚

P0 告警处置:
告警触发 -> 自动通知 -> 管理员认领 -> 查看影响范围和最近变更 -> 执行预案或降级 -> 恢复验证 -> 关闭工单 -> 生成复盘记录

敏感数据授权查看:
管理员发起申请 -> 填写查看原因、字段、时长 -> 第二管理员/法务审批 -> 临时授权 -> 带水印脱敏查看 -> 自动过期 -> 审计日志归档
```

## 7. 组件与交互规范

| 组件 | 适用场景 | 规范 |
|---|---|---|
| 指标卡 | 总控台、监控、商业化 | 显示值、环比、阈值状态、点击进入明细 |
| 数据表格 | 情报、用户、订单、日志 | 支持筛选、排序、分页、列配置、批量操作 |
| 详情抽屉 | 情报、用户、工单、告警 | 从右侧打开，不打断列表上下文 |
| 全屏编辑器 | 知识节点、合规文案、复杂规则 | 支持草稿、预览、版本对比 |
| 复核面板 | 情报、知识、合规、敏感查看 | 展示证据、裁决、理由和下一处理人 |
| 确认弹窗 | 高风险操作 | 明确影响范围、回滚方式、二次输入确认 |
| 状态标签 | 告警、复核、订单、权益 | 颜色 + 文本，不使用纯颜色表达 |
| 全局搜索 | 流水号、用户、情报、订单、工单 | 支持快捷跳转和权限过滤 |

后台按钮应优先使用图标按钮表示常见命令，如查看、编辑、归档、导出、刷新、回滚、确认、关闭。无法仅靠图标理解的命令使用“图标 + 短文本”。所有图标按钮必须提供悬停提示。

## 8. 数据与 API 需求

管理员后台需要统一通过 `services/api` 调用，不直接访问数据库、采集器、AI worker 或监控组件。V3 后台 API 应覆盖总控台、知识库、采集、情报、台账、人工情报、风控、用户会员、商业化、告警监控、日志审计、合规报表。

所有写操作必须返回 `requestId`，前端在成功提示里提供“查看审计日志”入口。

## 9. 验收标准

| 维度 | 验收标准 |
|---|---|
| 范围完整性 | 覆盖 V3 管理员后台完整模块，并能支撑商业化、合规、审计和运维闭环 |
| 权限隔离 | 不同角色只能看到和操作授权范围内的数据，敏感数据查看需要双人审批 |
| 情报闭环 | 情报可从采集/录入、复核、权益确认、同步、引用到审计全链路追踪 |
| 知识闭环 | 知识编辑、版本对比、双人复核、发布、回滚完整可用 |
| 运维闭环 | 告警可认领、处理、关闭、复盘，并关联指标和日志 |
| 合规闭环 | 免责文案、灰色内容、巡检任务、审计证据包可管理 |
| 商业化闭环 | 用户、会员、订单、权益、报告交付和投稿激励可查询与处理 |
| 复用落地 | 基于现有 Next.js 工作台视觉和组件体系扩展，不引入无必要的重型 UI 框架 |
| 可访问性 | 图标按钮有可访问标签，表格支持键盘聚焦，高风险操作有明确文案 |
| 响应式 | 桌面完整操作，移动端支持告警、工单、日志和关键详情只读/轻操作 |

## 10. 分阶段落地建议

| 阶段 | 交付 |
|---|---|
| Admin-V3-1 | `AdminShell`、导航、权限门禁、总控台、告警入口、日志基础检索 |
| Admin-V3-2 | 情报管理、复核工作台、台账工单、人工情报 |
| Admin-V3-3 | 知识库管理、版本对比、双人复核、发布回滚 |
| Admin-V3-4 | 采集调度、数据源、关键词、风控规则、数据生命周期 |
| Admin-V3-5 | 用户会员、订单权益、报告交付、投稿激励 |
| Admin-V3-6 | 合规配置、巡检任务、月度报表、审计证据包、移动端应急视图 |

每个阶段都必须同步更新中英文文档和变更日志，并补充角色权限、API 契约、验收用例和回归测试。

## 11. Admin-V3-1 / Admin-V3-2 当前实现状态

首批完整闭环已进入实现，范围包括真实数据库表、启动自动补表、`services/api` 后台接口、`apps/web` `/admin` 管理页面和源码级回归测试。

已实现的后端能力包括：总控台聚合、告警列表与确认/认领/关闭、审计日志检索、情报复核与裁决、工单列表与流转、人工情报录入与审核。人工情报审核通过后会同步提升为正式情报记录；后台写操作会写入审计日志。

已实现的数据表包括：`admin_intelligence_reviews`、`admin_tickets`、`admin_human_intelligence`，并复用既有 `alert_events`、`audit_logs`、`intelligence` 表。表结构已进入 MySQL 初始化脚本，并由 API 启动迁移在既有库中自动补表。

已实现的前端能力包括：独立 `/admin` 路由、管理员登录与角色门禁、总控台、告警中心、日志审计、情报复核、台账工单、人工情报录入/审核。当前页面直接对接 `/api/admin/**`，不使用前端 mock 数据。

验证说明：当前执行环境未提供 `mvn`、`node` 或 `npm` 可执行文件，因此本次无法在该环境运行 Maven 与 Web 测试命令；已补充 `AdminV3ApiTest` 和 Web 源码回归测试，待具备工具链的环境运行。
