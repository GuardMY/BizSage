# BizSage V2 生产高可用工程版里程碑

## V2 范围

V2 是生产高可用工程版，将 V1 内部验证 MVP 升级为可支持小规模付费用户灰度的系统，重点补齐监控稳定性、可恢复性、权限隔离、经营诊断 PDF 报告和 AI 推理控制。

V2 受 `docs/zh-CN/` 下治理文档及 `docs/en/` 英文对应文档约束。V2 只实现 `docs/zh-CN/milestones/product-milestones-zh-CN.md` 中定义的 V2/P0 子集。

系统必须验证：

- 核心服务在单组件故障时不打断核心诊断链路；
- 爬虫、API、缓存、队列和 AI 故障均有明确降级或故障切换路径；
- 生产灰度权限可以隔离免费和付费情报；
- 推理输出通过冲突、时效、地域、逻辑和合规检查；
- 运营人员可以在灰度期间监控、复核和恢复系统。

## 不在范围内

- 完整商业会员、订单、发票和客户成功自动化。
- 完整动态信源权重引擎；V2 可准备指标，V3 负责完整自动化。
- 每条数据的完整血缘；V2 记录足够支撑复核和回滚的血缘。
- H5 完整移动端体验和会员中心。
- 五类完整报告；V2 只交付经营诊断 PDF。
- 99.9% 商业 SLA 承诺；V2 记录灰度稳定性证据。

## 里程碑计划

### M0 V1 退出复盘与灰度范围锁定

- 复核 V1 验收结果。
- 记录所有已批准的 V1 遗留修复任务。
- 锁定 V2 灰度用户范围、付费/免费数据边界、回滚标准和支持窗口。

验收：只有在 V1 退出缺口和灰度边界均记录并批准后，V2 才能开始。

### M1 运维工程底座

- 增加爬虫页面、API 响应、全局知识、局部维度情报的多级 Redis 缓存策略。
- 增加开发、测试、预发、生产灰度环境隔离。
- 增加 MySQL 和向量数据备份恢复脚本。
- 增加 API、collector、AI worker、缓存、队列、数据库和业务链路监控指标。
- 增加三级告警规则和响应负责人。

验收：完成备份恢复演练，核心指标可在大盘查看，告警可被受控触发。

### M2 韧性采集

- 增加页面 MD5 和正文 SimHash 的增量爬虫指纹。
- 增加分级重试、指数退避、域名熔断和死信分类。
- 增加代理厂商轮换和 IP 冷却。
- 增加第三方 API 多厂商故障切换、响应缓存和近期快照兜底。
- 增加采集成功率、API 调用量、缓存命中率和信源健康度埋点。

验收：爬虫故障、API 厂商故障和队列堆积均进入定义好的兜底路径。

### M3 数据治理与知识

- 增加新旧信息冲突引擎，区分短期波动、地域特例、权威永久更新、存疑冲突和虚假信息。
- 增加日、周、月时序快照。
- 增加知识更新行级乐观锁和多源合并。
- 增加用户私有、地域、行业、付费/免费四层基础数据隔离。
- 增加动态实时情报知识库和生命周期元数据。

验收：冲突情报可被标记或进入复核，快照可查询，权限过滤阻止跨边界读取。

### M4 RAG 与 AI 推理控制

- 增加时序、地域、行业和权益检索过滤。
- 增加六维重排：权威度、时效、地域、行业、复核置信度和历史质量。
- 增加长情报上下文压缩。
- 增加多模型路由和降级兜底。
- 增加事实、时效、地域、逻辑和合规五道自检。
- 增加角色、行业、地域、合规、格式、来源/免责声明分层 Prompt 库。

验收：验证场景证明无依据不下结论、冲突可标注、地域可过滤、故障可兜底。

### M5 入行学习 Agent 与双 Agent 联动

- 增加入行学习 Agent 基础流程。
- 增加短期会话记忆、基础长期用户画像记忆和 90 天自动遗忘规则。
- 增加诊断和学习上下文的一键互跳。
- 统一双 Agent 输出格式：证据、时效、置信和免责声明。

验收：用户可从诊断跳转到薄弱链路学习，也可从学习跳转到诊断，行业上下文不丢失。

### M6 权限、付费灰度与报告

- 增加双层 RBAC：功能权限和数据权限。
- 隔离免费和付费情报。
- 增加用户基础画像：行业、地域、会员等级、咨询偏好。
- 增加投稿激励基础流程，复核通过后生效。
- 增加带来源和免责声明的经营诊断 PDF 导出。

验收：付费用户可访问灰度付费情报和 PDF 报告，免费用户无法读取付费专属记录。

### M7 运营后台与复核工单

- 增加采集、API、AI、缓存、队列和业务指标大盘。
- 增加存疑信息和冲突信息复核工单。
- 增加告警中心和处理状态。
- 增加核心操作审计日志检索。

验收：运营可定位失败采集任务、复核存疑情报并追踪相关日志。

### M8 灰度验证

- 运行 API、collector、AI worker 和 Web 测试命令。
- 执行备份恢复演练并记录 RTO/RPO。
- 针对爬虫、API 厂商、模型供应商和数据库执行故障演练。
- 执行隐私脱敏和权限隔离检查。
- 记录 7 天灰度稳定性、故障和修复任务。

验收：V2 只有在验证完成，或每个失败项都有批准的修复任务和负责人时才能退出。

## 验收清单

- [ ] V1 退出缺口已复核并记录。
- [ ] 多级缓存已配置并可度量。
- [ ] 验证数据中增量爬虫减少至少 60% 无效请求。
- [ ] 可缓存 API 场景的缓存命中率达到至少 70%。
- [ ] 演练条件下爬虫 RTO 小于 10 分钟。
- [ ] 数据库恢复证明数据丢失不超过 6 小时。
- [ ] 全链路日志留存不少于 6 个月。
- [ ] 设计存储和日志中未发现明文敏感用户数据。
- [ ] 免费和付费情报通过权限校验隔离。
- [ ] 经营诊断 PDF 包含来源、时效、置信和免责声明。
- [ ] AI 自检可标注冲突并阻止无依据结论。
- [ ] 灰度运行 7 天无重大故障，或故障已有批准修复任务。

## 验证命令

- API：在 `services/api` 运行 `mvn test`。
- Collector：在 `services/collector` 运行 `python -m pytest`。
- AI worker：在 `services/ai-worker` 运行 `python -m pytest`。
- Web：在 `apps/web` 运行 `npm test` 和 `npm run build`。
- 文档：移动或修改文档后运行 Markdown 双语配对检查。

如果当前环境无法运行 Docker、压测、恢复演练或 7 天稳定性验证，必须在 V2 验证文档中记录尝试命令、原因和修复步骤。
