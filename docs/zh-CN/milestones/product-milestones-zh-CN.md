# BizSage 产品全版本里程碑

## 目的

本文档是 BizSage 的跨版本里程碑路线图。迭代阶段以 `raw-docs/行业智能创业Agent平台全域完整架构设计文档（V4.0_全域封顶终版）配套分阶段落地开发规划说明书.pdf` 为准。

当前生效的实施里程碑是 V2。V1 自动化验证已完成，遗留的环境验收缺口纳入 V2 M0 修复项跟踪。V3 在 V2 灰度退出标准满足并获批前仍为规划目标。

后续所有功能开发在实施前必须检查并遵循以下治理文档：

- `docs/en/product-strategy-and-design.md` / `docs/zh-CN/product-strategy-and-design-zh-CN.md`

源 PDF 的阶段模型为：

1. V1：MVP 最小可用版，内部验证。
2. V2：生产高可用工程版，对外灰度。
3. V3：全域商业化封顶终版，全量正式上线。

## V1 MVP 最小可用版

详细计划：`docs/zh-CN/milestones/v1-mvp-milestones-zh-CN.md`。

### 范围

- 通过 mock 或可插拔适配器实现四类数据源采集。
- 实现数据治理、字段归一化、去重、固定信源权重、谣言过滤和敏感数据保护。
- 实现静态知识库、RAG 检索和带来源输出的诊断 Agent。
- 实现 Web 登录、会话、诊断聊天、来源查看和简单运营控制台。
- 实现本地单节点基础设施、运行手册和验收文档。

### 退出标准

- 四类数据源可以写入标准化记录。
- 诊断回答包含来源、时效说明、置信提示和免责声明。
- 无证据请求返回信息不足提示，而不是无依据结论。
- 手机号和身份类敏感字段按设计加密或脱敏。
- 完成 50 并发 API 请求和 4 小时单节点观察，或记录明确修复任务。

### 不在范围内

- Android 实现，除占位文档外不开发应用功能。
- 付费会员、权益计费和商业订单流程。
- PDF 报告。
- 多模型路由。
- 动态信源权重。
- 高可用、灾备和完整监控大盘。

## V2 生产高可用工程版

详细计划：`docs/zh-CN/milestones/v2-production-high-availability-milestones-zh-CN.md`。

### 范围

- 补齐生产工程底座：多级缓存、弹性伸缩、完整熔断/降级/死信队列、灾备恢复、环境隔离、监控、告警和 SLA 统计。
- 增加高可用采集能力：增量爬虫、代理轮换、故障切换、多厂商第三方 API、API 缓存、时序兜底和采集埋点。
- 增加进阶治理：新旧信息冲突引擎、时序快照、行级乐观锁、多源合并和四层基础数据隔离。
- 增加动态情报知识库、时序知识库、AI 知识精炼、完整生命周期管理和增强 RAG 过滤/重排。
- 增加多模型路由、五道推理自检、分层 Prompt 库、降级兜底、入行学习 Agent 基础能力、Agent 记忆和双 Agent 互跳。
- 增加经营诊断 PDF 导出、双层 RBAC、免费/付费情报隔离、用户基础画像、投稿激励基础流程、运营大盘和复核工单。

### 进入标准

- V1 退出标准已满足，或所有 V1 剩余失败项已有批准的修复任务。
- V1 API、数据库、部署、验收和里程碑文档均已保持中英文同步。
- 生产灰度目标场景、数据边界和回滚标准已记录。

### 退出标准

- 单组件故障不中断核心业务；爬虫故障 RTO 小于 10 分钟，第三方 API 故障可切换厂商。
- 数据库可通过备份恢复，数据丢失不超过 6 小时。
- API 缓存命中率不低于 70%，增量爬虫减少至少 60% 无效请求。
- 全链路日志留存不少于 6 个月，隐私脱敏完整，无明文隐私泄露。
- 付费用户权限开通和专属诊断 PDF 报告在灰度环境可用。
- 灰度稳定运行 7 天无重大故障。
- AI 推理具备冲突标注，验证场景中无跨地域错误输出。

## V3 全域商业化封顶终版

详细计划：`docs/zh-CN/milestones/v3-full-domain-commercial-final-milestones-zh-CN.md`。

### 范围

- 落地动态信源权重、完整数据血缘、过期/死信/测试脏数据自动清理和完整热/温/冷存储生命周期。
- 完成四层多租户物理隔离、付费情报独立分库、完整会员权益体系、订单、套餐和客户运营。
- 增加五类完整报告：科普、市场调研、诊断、专题风险、周期复盘。
- 完成精细化用户画像、个性化运营、用户投稿完整激励和商业运营自动化。
- 完成统一网关与安全体系：防爬、防批量导出、垂直/水平越权校验、输入/输出风控审计和管理员操作审计。
- 完成 H5 移动端适配、弱网降级、会员中心、历史对话、报告下载、审计日志后台、月度运营报表、标准化交付资产和 99.9% SLA 能力。

### 进入标准

- V2 灰度退出标准已满足。
- 商业定价、会员分层、权益模型、合规假设和交付资产已批准。
- 安全、可靠性、数据隔离和成本目标可度量。

### 退出标准

- 可用性 SLA 不低于 99.9%，全年故障时长不超过 8.76 小时。
- 商业化闭环完整：付费会员、权益隔离、报告交付、用户投稿激励全流程自动化。
- 合规就绪覆盖全链路审计日志、隐私加密脱敏、数据隔离和等保核查所需安全风控。
- 数据治理支持动态权重自动更新、数据血缘全链路追溯和垃圾数据自动清理且无存储膨胀。
- PC 与 H5 移动端完整可用，弱网和接口故障均有友好兜底。
- 交付资产齐全：架构文档、部署脚本、运维手册、故障预案、压测报告和接口文档。

## 跨版本规则

- 每个版本在开始实施前，必须先拥有自己的详细里程碑文档。
- V1 期间不得实施后续版本功能，除非同步更新 V1 里程碑文档并接受范围变更。
- 文档必须在同一次改动中维护英文和中文版本。
- 功能变更必须更新 `CHANGELOG.md` 和 `CHANGELOG-zh-CN.md`。
- 里程碑进度变更必须更新对应里程碑文档。
- Web、API、worker、collector、基础设施和 Android 模块必须保持目录隔离，并通过有文档的接口通信。
